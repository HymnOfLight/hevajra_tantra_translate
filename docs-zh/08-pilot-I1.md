## 1 怎么跑的

- **命令**：`hevajra-matrix collate --chapters I.1 --replicates 1 --backend subscription`
- **运行目录**：`runs/pilot-20261010T145135Z`。不入库，与响应缓存一起私下保存。
- **工具版本**：Claude Code 2.1.296，模型 `claude-opus-5-5`，effort high，提示词 `collate.v1`。
- **请求**：I.1 共 163 个参照单元，分 2 个窗口，所以是 2 次调用。
  - 第一个窗口单独先跑，写入提示缓存；第二个窗口随后读取这份缓存。
- **跑之前的检查**：先做了两轮只读代码审查。
  - 第一轮由 4 个视角各自审查，每条发现再由 3 名质疑者核对。
  - 第二轮是逐项复核。
  - 修复的问题包括：状态归类的顺序、超时与重试、额度用完的识别、只允许包月登录、关闭自动换模型、运行目录绑定后端等，见提交 `831eb30` 与 `4fe05b0`。

## 4 看起来对的地方（有待专家确认）

- **以音译行遮蔽**：序分"住于金刚妃之 bhaga"一句，汉文作"金剛喻施婆倪"，被标为音写。这正是先行研究讨论的现象。
- **教义上的替换**：焚烧"五如来"在汉文中成了"焚棄五蘊"，焚烧"佛眼母等"成了"以佛眼母焚燼諸漏"（受事变成了施事）。这两处都被标为替换。
- **三十二脉名表**：汉文以序数加略称排列，与藏文逐项错位，被逐一标出。

## 5 试跑暴露的方法问题（开发集阶段要定）

1. **固定的译名被算作"替换"**：Hevajra 作"空智金剛"、Heruka 作"空智"，是全经统一的译名，不是对内容的改写。现在它们被标为 substitution，会抬高 D_any。
   - 建议：在码本与提示词里写明，全经一贯的专名对译算 equivalent（或 paraphrase）；再用开发集金标准检验。
2. **专名音写算不算偏移**：现行规则把非真言单元的音写一律算作"在场偏移"。但脉名（lalanā、rasanā、avadhūtī → 羅羅拏、辣娑摩、阿嚩底）之类专名的音写，和"以音译行遮蔽"不是一回事。
   - 建议：增加"专名音写"一类，或加一个标记，与内容音写分开统计。
3. **列表被压缩成总称**：三身、语、意五项都链接到"三身三業"一处，被标为 category_name_omitted（类名略去）。按定义更接近 generalised（概括）或 abridged（部分）。
   - 码本里这两类的界线需要配例句说清。
4. **跨窗口的"属于别处"**：只对勘一品时，第二品的真言段落被列为 belongs_elsewhere，并产生 `unaccounted` 诊断。全经对勘时这些应当会消失，到时再核对。

以上几点都只能靠开发集金标准来定。这也说明，先做开发集的人工盲标是必要的。
