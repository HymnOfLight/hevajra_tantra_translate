## 1 仓库布局

```
hevajra_tantra_translate/
├── README.md              英文简介；中文读者请看 docs-zh/README.md
├── pyproject.toml         依赖只有 PyYAML；可选 [claude] = anthropic，[dev] = pytest
├── config/                运行参数（英文 YAML）
│   ├── run.yaml           路径、见证、窗口与动态规划参数、复核分钟数与语言能力
│   ├── llm.yaml           模型、价格、预算上限、各任务的 effort / max_tokens / 重复次数 / fallback
│   └── preregistration.yaml  估计量、测试窗抽样种子、门控阈值、核验与抽检方案（打开测试金标准前冻结）
├── data/                  全部多语种材料（键与注释英文，值可以是任何语言）
│   ├── registry/          见证清单、章级概表 v2（多对多、可按单元范围切分）
│   ├── lexicon/           锚点词表、数词、德格标记、夹注分类规则、否定词、异体字、动机词表
│   ├── codebook/          主题词表、对勘与组件的合成示例
│   ├── sentinels/         哨兵事实
│   ├── annotations/       人工数据：金标准、核验裁决、主题标签（只含 id 与短引文）
│   ├── ledger/            测试集评估账本（只追加）
│   ├── experiments/       过度归因实验条目（只含坐标）
│   ├── fixtures/          单元测试输入（迷你 CBETA、迷你德格、归一化用例等）
│   ├── raw/               下载的原文（不入库）
│   └── reference/         研究者自备的梵文 TSV（不入库）
├── docs/                  英文开发者文档：架构、数据格式、LLM 任务、贡献规范
├── docs-zh/               中文用户文档（仓库里唯一的中文散文，除 data/ 外）
├── hevajra_matrix/        代码（全英文）
├── tests/                 unit（默认）/ integration（真实数据）/ live（真实 API）
└── runs/                  每次运行的输出与 LLM 响应缓存（不入库；缓存含受许可限制的原文）
```

**语言规范由测试强制**：`.py` 文件里任何位置（注释、docstring、字符串字面量）都不得出现中文、藏文、天城体等非拉丁文字；文字常量写成 `\u` 转义并附英文注释，或放进 `data/lexicon/`；`docs-zh/` 与 `data/` 以外的 Markdown、`config/` 的 YAML、所有 YAML 的键与注释都必须是英文；文件名与目录名一律 ASCII。梵文 IAST 转写属于拉丁字母，可以出现在注释里。

## 2 代码工作流与依赖

实施按批次进行（本机同时只能跑两个实现 agent）：第 1 批 WS1 内核 ∥ WS4 Claude 客户端 → 第 2 批 WS2 切分与登记 ∥ WS3 基线 → 第 3 批 WS5 对勘 ∥ WS9a 主题 → 第 4 批 WS8 统计 ∥ WS10 实验（实验是独立的早期轨道，只依赖内核、客户端与主题码本）→ 第 5 批 WS6 矩阵与复核 ∥ WS9b 组件层 → 第 6 批 WS7 评估 → 第 7 批 WS11 流水线与报告 → WS12 文档定稿，最后做多视角对抗式代码审查。WS1 先冻结 `core/types.py`，WS4 先冻结 `llm/client.py` 的接口，并行的工作流都针对稳定的类型编码。

| 工作流 | 内容 | 验收要点 |
|---|---|---|
| WS0 骨架 | 目录分类、搬迁数据与文档、英文 README、`config/*.yaml`、配置加载、语言规范测试 | 不装 `anthropic` 也能安装运行；语言规范测试通过 |
| WS1 内核 | 类型、稳定 id、文本归一化、词表加载、I/O 工具 | 插入一条夹注只改变该行的序号；数词按词界匹配（lakṣaṇa 不再被当成十万）；真实数据上 id 零重复 |
| WS2 切分与登记 | 夹注 7 类、181 条脚注、德格副文本与异文、题记元数据、概表 v2、见证清单更正、哨兵文件 | 真实数据上 521/181/26/3 等计数全部吻合；合并品一对多映射正确 |
| WS3 基线 | 动态规划输出 `Alignment`；零相似度与修正后的锚点相似度；洗牌对照 | ཤ 不再命中 ཤེས；嚩日囉 不再命中"日"；真实数据上基线 60 秒内跑完 |
| WS4 Claude 客户端 | 协议、SDK 适配、缓存、审计、假客户端、schema 校验、Batches 预热、`claude-check` | 拒绝（有/无类别）、截断、无效 JSON、模型替换、思考块被忽略都有测试；离线模式缓存未命中即报错；审计日志不含原文；预算上限生效 |
| WS5 对勘 | 窗口规划、请求构造、V1–V11 核验、共识、扰动、提示词与合成示例 | 每条核验规则一个测试；请求中不含梵文、脚注与主题；伪造的 II.9→18 链接变成越窗诊断 |
| WS6 矩阵与复核 | 关系→状态表、单元格构建与优先级、盲标/揭示/导入表格、分层抽样与队列 | 盲表不含任何机器列；导入会剥去原文；过期裁决只列出不套用 |
| WS7 评估 | 金标准评分、门控、哨兵八种检查、测试窗抽样、账本 | 手算的 P/R/F1/κ 用例；门控的"区间下限高于对照上限"规则 |
| WS8 统计 | 两阶段估计、Δ、分解与零模型、功效、见证距离 | 在合成数据上覆盖率 ≥0.9；能恢复植入的效应；分解总和断言 |
| WS9 组件与主题 | T2、T3 及其核验 | T3 请求只含参照文本；未知主题被拒 |
| WS10 实验 | 条目、条件设计、受试/评分请求、否定感知词表规则、分析 | 模板不含动机词；评分请求不含条件；"This is not censorship""並非刪略"判为否定 |
| WS11 流水线与报告 | 各阶段函数、`run`、清单、分级报告、`prereg freeze` | 离线端到端；描述级报告中不出现任何比率或 Δ |
| WS12 文档 | 英文 `docs/` 与中文 `docs-zh/` | 语言规范；链接全部可达；每个 CLI 子命令、每个表格列都有说明 |

## 3 这次提交做到哪一步

**本次在新分支 `claude/brave-bell-7rb7lh` 上完成**：WS0–WS12 的全部代码与测试；在真实 T0892 与德格本上跑通不需要 API 的阶段（切分、基线、G0 与切分阶段哨兵）；Claude 相关代码全部用假客户端测试。

**本次做不到、需要您来做的**：

1. **API 密钥**：开发容器里没有 Anthropic 密钥，所以没有做任何真实调用。拿到密钥后先跑 `hevajra-matrix claude-check`（一次极小的调用，打印实际服务模型与用量），再用 `collate --dry-run` 估算费用，然后在 I.1 上实测藏文的 token 数。
2. **专家工时**：金标准、核验、抽检、主题确认都只能由懂藏、汉（与梵）文的人做。代码负责出题、记账、回写和统计。
3. **数据**：梵文写本列（Conlon 在线校本需征得许可）、第二部甘珠尔（Them spangs ma 系，如 Stok 或伦敦本）。没有这些，分解（E3）会如实打印 `NOT_ESTIMABLE`。

## 6 已定的设计取舍（本次综合中作出）

- Claude 的核验后链接**就是**对齐结果；单调动态规划只作基线，因为它会抹掉真实的换位（II.3）。
- 金标准只接受盲标；看过机器结论的裁决只进矩阵、不估误差。
- 测试集概率抽样；审查推荐的难品作开发集与哨兵。
- 对普查量不做品区组自助法；Rogan–Gladen 校正因在 Se+Sp−1 小时不稳定而不用，改用两阶段估计。
- 砍掉的东西（KISS）：诱饵题、Neyman 分配、四级报告、GLMM、嵌入、记忆探针、遮蔽臂、三种问法、双评分器版本、HTML 复核卡、哨兵小语言、由码本生成枚举、自动重试与拆窗、漂移金丝雀（改由评估账本比对各次运行）。
- 暂缓到有需要或有数据时再做：Batches 预热缓存（省钱但多一条代码路径）、分解的循环平移零模型与各写本优势比（要等梵文写本列）。T2 组件层实现但只作描述，不进入任何估计量。
- 《老子》迁移模块在本分支移除；原先文档中乙本年代（"不避恆讳"反说明抄于文帝即位之前）与章序（应为 21→24→22，且漏了 80、81 章移到 66 章之后）的两处错误记在这里，将来移植回来时一并改正。
