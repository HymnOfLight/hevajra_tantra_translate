## 0 一页摘要

**研究问题**：宋代法护等译《佛说大悲空智金刚大教王仪轨经》（大正藏 T0892）在翻译《喜金刚本续》时，哪些内容被省略、改写或只作音写？这些变化在"敏感"内容（性、肉食、伤害、不净物等）上是否更多？各项变化中，哪些来自梵文底本，哪些是译者所为？

**旧版（v0.2，`main`）的问题**：2026-09-30 的代码审查（全文在 [`reference/2026-09-30-code-review.md`](reference/2026-09-30-code-review.md)）在真实文本上复现了流水线，发现三点：

- 头条数字"汉译缺失率 18.4%"与"相似度恒为 0""随机向量"两类安慰剂的结果区间重叠，**无法与噪声区分**；
- 四处原文抽查全部判错；
- 仓库里没有任何人工金标准，所以根本无从知道结果对不对。

**新分支做了什么**：重新设计方法，几乎重写了全部代码，具体是：

- 新方法叫 **VEC（Validated, Evidence-graded Collation，经验证、证据分级的对勘法）**。
- 用 **Claude Opus 5.5** 整品逐句对读，取代原来的 Qwen3 与"长度＋锚点"对齐。Claude 只负责提出对应关系；每个链接、每段引文都由代码逐字核验，最终的判断由人来做。
- 任何比率都必须先在**盲标金标准**上通过**预注册门控**，并且显著优于"不读内容"的对照组，才能被打印出来。
- 人工核验以**两阶段抽样**的方式校正机器的误差，数字附带区间。
- 新增一个独立的**过度归因实验**，检验 LLM 是否会在证据不支持时仍断言"译者出于审查而删改"。
- 梵文层的接入代码已经写好，数据一到即可运行。

**规模**：

|---|---|

## 1 背景：为什么要改

### 1.1 旧版做了什么

v0.2 的思路是"见证矩阵"：

- **行**：以德格本（D417–418）藏译的句或偈行为临时参照单元，约 3,045 个。
- **列**：各见证，实际上只跑了汉译 T0892 一列。
- **对齐**：先用藏汉锚点词计算相似度（也可换成嵌入向量），再用单调动态规划把参照单元配到汉文片段上。
- **状态判定**：没配上的单元记为 ABSENT；配上了但汉文长度不足基线一半的，记为 PARTIAL。
- **LLM 的用法**：通过 vLLM/transformers 部署 Qwen3，在 RTX 5090 上运行，承担 R1–R9 九个角色（嵌入、对齐复核、命题切分、组件预填、主题预标、归因、反事实、记忆探针、逐格说明）。
- **动机判断**：另用正则表达式从文本中识别"审查""删略"等动机。
- **其他**：附带一个《老子》多版本的迁移研究模块。

### 1.2 审查发现了什么

| 审查发现 | 根因 |
|---|---|
| "缺失率 0.184 [0.128, 0.238]"与纯长度对照（0.108）、三组随机向量（0.229–0.244）的区间重叠；只换相似度后端，ABSENT 集合几乎不相交（Jaccard ≤ 0.025） | 75.9% 的非空对齐珠相似度为 0，即四分之三的对齐只靠长度；81% 的"偏移"是只按长度判定的 PARTIAL |
| 仓库中没有任何人工金标准 | 先建模型，后谈验证 |
| 四处原文抽查全错：<br>• I.7 十二处类名被略去<br>• II.3"你当杀生"在汉文中反转为"不應殺害"<br>• II.9 的开头实际并入汉文第 18 品<br>• 汉文末尾三偈在藏文中没有 | 单元层与长度模型看不见这类现象；按"品"做的硬性限制把跨品的对应切断了 |
| 人工复核写出去就回不来，证据等级永远是 C | 缺少回写通道 |
| 品区组自助法只量了"抽到哪些品"的波动，没有量对齐误差 | 统计设计与误差来源错位 |
| 三分分解不穷尽、把校勘本当独立见证、没有零模型、"共享"一类受德格修订层污染 | 分解定义不严 |
| 动机正则把"这不是审查"也算作断言审查；Qwen3 的思维链泄漏进输出 | 评分规则与部署缺陷 |
| 若干文献与事实错误（德重 2026 的数字、Isaacson 的页码、宣奴贝的译名、明抄本的性质等） | 未打开原始来源核实 |

审查列出的 26 项代码缺陷逐项对应到新代码与验收测试，对照表在英文文档 `docs/architecture.md`。

审查对研究价值的判断也被采纳为设计约束：**问题值得做，但真正的瓶颈是专家工时与写本数据**。因此自动化的任务是节省检索和记账的时间，新方法的每一步都要回答两个问题：它省了专家多少时间？它出错时怎样被发现？

### 1.3 设计过程

1. 四个独立视角各出一套方案：方法学/统计、文献学、软件架构、LLM 测量工具。
2. 三位评审打分：数字人文会议审稿人、五年期维护者、审查作者。
3. 综合四套方案，再逐条对照审查做完整性核对。
4. 研究者作了四项决定：
   - 《老子》模块在新分支移除；
   - 报告用英文输出，另附中文术语表；
   - 数据 YAML 中的说明改为英文，原文保持原文；
   - 服务器端 fallback 在流水线任务中开启，在实验中关闭。
5. 按 13 个工作流（WS0–WS12）实施。
6. 多视角对抗式代码审查，确认 64 项问题，全部修复。
7. 在真实文本上做模拟的完整研究周期，又修复一批集成问题；回归审查再修一批。

## 3 新方法 VEC 的核心思想

一句话概括：**Claude 提出，代码核验，人来裁决，先盲后揭；先验证，后度量。**

八条原则：

1. **先验证，后度量。** 机器产生的比率只有在测量工具通过预注册门控之后才会被打印。门控有两个要求：在封存的、概率抽样的盲标测试集上达到绝对门槛；并且置信区间下限高于所有"不读内容"的对照组。不过关时，报告是"描述级"，只输出标注为"未经验证的工具输出"的计数。人工核验过的计数随时可以输出，因为它不依赖工具。
2. **状态来自内容证据，从不来自长度。** PARTIAL 与 ABSENT 必须有经核验的关系。长度只作为描述性维度 `d_len`。
3. **Claude 是有误差率的测量工具，不是神谕。** 为此有五项措施：
   - 冻结的提示词与 schema 哈希（"工具指纹"）；
   - 严格 JSON 输出，流水线任务中不含自由文本；
   - 每个 id、每段引文都由代码核验；
   - 每品重复 3 次；
   - 响应缓存与审计日志。
4. **构造上的盲法。** 盲法由代码保证，而不是靠使用者自觉：
   - 对勘调用只看一个参照、一个见证，不给梵文、大正藏脚注或主题标签；
   - 主题预标只看参照文本，从不看汉文；
   - 实验评分器看不到实验条件；
   - 人工金标准、抽检、首轮核验都看不到机器结论。
5. **每个数字都说明自己估计的是什么。** 估计量、总体（普查还是超总体）、适用范围、报告级别、区间覆盖了哪些误差来源都随数字一起打印。无法估计时打印 `NOT_ESTIMABLE: <原因>`，**绝不打印 0**。
6. **以专家工时为预算的误差校正。** 罕见而重要的类别全部人工核验；常见类别分层抽样；一个后验预测插补机制服务所有估计量。
7. **坐标就是键。** 人工裁决以"见证原生坐标＋文本指纹"为键，每次构建都重新套用；原文变了（指纹不符），裁决就只列出、不套用。
8. **工程上 KISS/SOLID。** 函数式内核，外面是一层薄薄的命令行与文件读写：
   - Claude、基线、安慰剂、金标准共用一种 `Alignment` 类型，所以比较天然公平；
   - 只在已有两个以上实现的地方设协议（`LLMClient`、`Similarity`）；
   - 依赖只有标准库＋PyYAML，`anthropic` 是可选依赖且延迟导入，不装它也能运行全部非 API 阶段。

### 3.1 流水线

```
fetch → ingest ─┬→ baselines（P1 纯长度、B0 锚点 DP、外部导入）─────────────┐
                ├→ collate（Claude T1，3 次重复）→ build → evaluate → stats → report
                ├→ topics（Claude T3 预标 → 人工确认）─────────────────────┘
                └→ components（Claude T2，组件层，描述性）
review export / import / reveal（人工盲标与核验，任何时刻都可进行）
experiment overattribution plan / run / score（Claude T4 受试、T5 评分）
```

每个阶段是一个普通函数，对应一个命令行子命令。阶段之间通过 `runs/<UTC时间>-<git短哈希>/` 下的文件传递，不用工作流引擎。`run` 子命令把能跑的阶段一次跑完。

## 4 Claude Opus 5.5 的角色

### 4.1 五个任务

| 任务 | 输入 | 输出 | 用途 |
|---|---|---|---|
| **T1 整品对勘器** | 一个参照品块（≤150 单元，相邻块重叠 10 单元）；完整汉文全文，作为可缓存的静态前缀，含夹注行，不含脚注与坐标；"核心窗口"，即概表映射的汉文品 ±1 | 每个参照单元的链接、关系类型、是否极性反转、置信度、两侧逐字引文；另列仅见于汉文的片段 | **测量工具**，结果进入矩阵 |
| **T2 组件编码器** | 已对齐的单元对（全文，不截断） | 九个槽位（施事、动作、受事、工具、处所、数量、条件、否定/情态、结果）各编为 ret/gen/sub/lit/om/add 之一，外加极性反转标记与引文 | 描述性的"译法剖面"；不进入任何估计量 |
| **T3 主题预标器** | **只有参照文本**（由函数签名强制，并有测试断言） | 多标签主题＋逐字线索 | 为人工确认排序、预填；主题标签最终由人决定 |
| **T4 实验受试者** | 实验条目 | 解释（≤120 词）、最可能原因（七选一）、前提是否成立 | 过度归因实验的研究对象 |
| **T5 盲评分器** | **只有**受试者的解释文本 | 对六类原因各给"断言 / 假设 / 否定 / 未提及"，另给主原因与动机引文 | 否定感知的结果编码，由人工锚定 |

旧角色的去留：

- R1（嵌入）、R2（对齐复核）由 T1 取代；R4（组件预填）由 T2 取代；R5（主题预标）由 T3 取代；R7（反事实）由 T4 取代；旧的动机正则由 T5 取代。
- R3 命题切分被弃用：LLM 切出的单元每次运行都会变，行标识就不稳定了。
- R6 LLM 归因被弃用：在流水线里让 LLM 判断动机，正是实验要研究的那种偏差。
- R8 记忆探针被弃用，由受试者输出中的"前提是否成立"字段替代。
- R9 逐格说明被弃用：逐字引文加关系码本身就是说明，而自由文本会招来动机措辞。

### 4.3 API 用法与技术约束

**请求方式**：

- 模型 `claude-opus-5-5`，通过官方 `anthropic` SDK 调用，统一用流式接口。
- 不传 `thinking`：该模型的思考恒开，无法关闭。
- 不传 `temperature`：该模型不接受采样参数。
- 不用预填，不用工具。
- 结构化输出用 `output_config={"effort": ..., "format": {"type": "json_schema", ...}}`，schema 为严格模式。
- 系统提示与汉文全文上设 `cache_control` 断点：全文只需付一次写缓存的费用，以后读缓存很便宜。

**不可复现性的对策**：由于不能设温度，同一请求每次的结果可能不同。对策有三：

- 内容寻址的响应缓存：`--offline` 模式下无需密钥即可逐字节重放；
- 每品重复 3 次并投票；
- 工具指纹（模型＋提示词＋schema＋effort＋参数的哈希）一变，就视为新工具，须重新过门控。

**拒绝**：`stop_reason == "refusal"` 被当作一种正常结果。系统记录拒绝类别，把该单元记为 `UNALIGNED(refused:<类别>)` 交给人工，不自动重试。

**服务器端 fallback（模型替换）**：

- 按研究者决定，流水线任务开启（beta `server-side-fallback-2026-07-01`），实验关闭。
- 代码通过响应中的 `model` 字段与 `usage.iterations` 检测是否发生了替换。
- 被替换的响应标记为 `substituted_model`，单元记为 `UNALIGNED(substituted_model)`。替代模型的草案只作为复核表中的提示（明确标明"FROM ANOTHER MODEL"），**永不进入测量统计**。
- G2 门控要求构成共识的对勘请求 100% 由所请求的模型产出。

**费用控制**：

- 配置中设有预算上限 $300，按 `<cache>/llm_spend.jsonl` **跨运行累计**。超出后，新的非缓存调用一律拒绝。
- 一个完整周期估计 $200–250（按同步价 $4/$20 每百万 token 计算）。
- 3 次重复的全经对勘干跑估算约 $65。
- **真正的约束是专家工时，不是钱。**

**审计**：每次调用（包括缓存命中）在 `llm_audit.jsonl` 中写一行：任务、提示词与 schema 哈希、请求与实际服务的模型、是否 fallback、停止原因、拒绝类别、用量、费用估计。**不含任何原文**，因为原文受许可限制。

**提示词**：五个版本化的提示词文件在 `hevajra_matrix/prompts/`（`collate.v1` 等）。示例一律用合成材料，从不使用哨兵或测试段落，以免"教会"模型通过考试。受试提示中不含任何动机词，由测试强制；所有提示都不要求模型"展示推理过程"。

## 5 数据如何被切分与登记

`fetch` 下载 CBETA 的 `T18n0892.xml` 与 Esukhia 德格本第 80 函，并记录 SHA-256。原文放在 `data/raw/`，不入库。

`ingest` 做以下几件事：

- **汉文**：切成正文片段（真实数据上 2,575 个）与夹注片段。521 条夹注按 7 类无遗漏地分类：音注 344、真言编号 162、反切 9、替换说明 2、卷次 2、题注 1、底本陈述 1。181 条大正藏脚注全部保留，其中 16 条注明东大梵本。
- **德格本**：切成句或偈行，真实数据上得到 3,042 个参照单元。卷末 རྫོགས་སོ 之后的内容标为副文本，并解析出三条译者题记；`{原字,校字}` 取校字，同时记录 26 处异文；修正了 visarga 的音节切分。
- **稳定 id**：由原生坐标派生，例如 `T0892:0592a29.1`、`D417:8a.4.3`；夹注加后缀 `.n1`；无坐标的孤立片段带 `+orphan`。每个片段另有 12 位十六进制的文本指纹，用来检测原文是否变化。
- **概表**（`data/registry/concordance.yaml`，schema v2）：记录藏汉品的对应及其证据，包括"II.9 开头 → 汉第 18 品""汉第 11 品 = I.11 + II.1""汉第 20 品 = II.11 + II.12"。概表只作为软窗口（映射品 ±1），不硬性切断跨品对应；越界的链接会变成"概表诊断"提交给人看。
- **G0 完整性检查**：id 无重复，以上各项计数全部吻合，副文本已分离，切分阶段的已核实哨兵全部通过。

设计阶段在原文上新核实了八点，均需专家确认，对应的哨兵现为 `proposed`：

1. I.7 十二处的十二个类名全部被换成序数，不只是略去"尸林"。
2. melāpaka 地名表藏汉都缺，与夹注"七者、八者，梵本元闕"相对应。
3. 汉第 11 品 = I.11 + II.1。审查据此推断"东大梵本分品不同"，这一推断不成立。
4. II.9 末尾的施食真言有对应，所以抽字法部分并非全部缺失。
5. II.12 的说明文字被当作真言音写，并且缺"心-吽"一项。
6. 卷一题注"三十一分中略出"是全经传统的自述，**不能**作为译者删节的证据。
7. 181 条脚注中没有任何宋、元、宫本异读，可见汉文列是经明代传抄的单一见证。
8. 夹注可无遗漏地分成上述 7 类。

文献更正（德重 2026 的数字、Isaacson 2022 的页码、宣奴贝的译名、明抄本是注疏而非根本续译本、MITRA 的仓库名等）已经写进 `data/registry/witnesses.yaml` 与文档。

## 6 对勘：从 Claude 回答到矩阵单元格

### 6.1 请求的构造（`collate/windows.py`、`collator.py`）

- 每个德格品切成 ≤150 单元的块，相邻块重叠 10 单元。
- 提示词中使用局部句柄：参照单元为 `r001`，汉文片段为 `z0001`。这样模型无需复制长坐标，代码负责把句柄映射回真实 id。
- 汉文全文作为可缓存的上下文发送，因此 Claude 能在全经范围内寻找对应。这正是 II.9 → 汉第 18 品这类跨品现象能够浮现的原因。
- 默认每品重复 3 次。`--chapters` 可以只跑指定品；`--dry-run` 只估算 token 与费用，不发送请求。

### 6.2 V1–V11 核验（`collate/verify.py`，全部是纯函数）

| 编号 | 检查内容 | 失败后果 |
|---|---|---|
| V1 | 覆盖：每个参照单元恰好出现一次 | 致命 |
| V2 | 句柄存在 | 致命 |
| V3 | 关系与链接一致（例如 `no_counterpart` 不应有链接） | 致命 |
| V4 | 引文逐字：归一化后必须是被引片段的子串；只在异体字折叠后才匹配的标为 `quote_variant_form` | 致命，或标记为 C 级 |
| V5 | 必填引文齐全 | 致命 |
| V6 | 极性一致：否定词只出现在一侧引文中，才算佐证 `reversal` | 非致命标记 |
| V7 | 越窗链接转为概表诊断 | C 级 |
| V8 | 交叉链接只标记、不删除（II.3 既是反转也是重排） | C 级 |
| V9 | 汉文侧穷尽：核心窗口内每个汉文片段要么被链接，要么列为仅见于汉文 | 汉文末尾三偈就是这样被抓住的 |
| V10 | 相邻块重叠部分的判断一致 | C 级 |
| V11 | 音写的字符比例检查 | 疑似"说明被音写" |

核验失败的单元不会悄悄变成 PRESENT 或 ABSENT，而是记为 `UNALIGNED(原因)`，并排在复核队列最前。

### 6.3 关系 → 状态（`matrix/status.py`，全仓库唯一推导状态的地方）

| 关系 | 状态 | 结果类 | 计入 D_any | 计入 D_cov |
|---|---|---|---|---|
| equivalent / paraphrase / expanded | PRESENT | 无偏移 | 0 | 0 |
| transliterated（参照为真言） | PRESENT | 无偏移 | 0 | 0 |
| transliterated（参照非真言，即"以音译行遮蔽"） | PRESENT | 在场偏移 | 1 | 0 |
| generalised / substitution / category_name_omitted / reversal | PRESENT | 在场偏移 | 1 | 0 |
| abridged | PARTIAL | 部分 | 1 | 1 |
| no_counterpart | ABSENT | 缺失 | 1 | 1 |
| 未解决（被拒、截断、无效、模型被替换、核验失败、无多数） | UNALIGNED(原因) | — | 不计 | 不计 |
| 汉文物理残缺 | LACUNA | — | 不计 | 不计 |
| 不在覆盖范围内 | NA | — | 不计 | 不计 |

主结果变量是 **D_any**（省略＋改写＋音写），与德重 2026 的口径可比；**D_cov**（只算部分与缺失）同时报告，与旧版的"0.184"可比。ABSENT 与 PARTIAL 永远分开报告。

### 6.4 共识与证据等级（`collate/consensus.py`、`matrix/build.py`）

三次重复按"结果类"投票，≥2/3 为多数；无多数记为 `UNALIGNED(no_majority)`。

| 等级 | 规则 |
|---|---|
| **A** | 指纹匹配的人工裁决（金标准，或核验、抽检、解决的终裁） |
| **B** | 3/3 重复一致，且所有核验通过 |
| **C** | 2/3 多数，或带任何非致命标记 |
| **X** | 核验致命失败或无多数 → UNALIGNED，排在复核最前 |

等级不代表"假定的准确率"，它是抽检的分层变量。各等级的实际准确率由抽检来测。

构建单元格的优先级是：**金标准 > 指纹匹配的人工终裁 > Claude 共识**。基线永远不进入矩阵。指纹过期的裁决写入 `matrix/stale_verdicts.csv` 等人重看。

## 8 统计：估计量与误差校正

### 8.1 估计量

| 编号 | 估计量 | 总体 |
|---|---|---|
| **E1** | θ_any、θ_A、θ_P：可计单元中 D_any、ABSENT、PARTIAL 的比例，分开报告 | 有限总体，即这一部经（普查，不做品区组自助法） |
| **E2** | 按参照音节加权的 θ（防止 3:1 对齐珠之类的切分伪影） | 有限总体 |
| **E3** | 分解：每个偏移单元归为底本、共享、残余等类 | 有限总体＋零模型 |
| **E4** | Δ：敏感与中性的分层风险差 | 超总体（翻译过程） |
| **E5** | 仅见于汉文的材料：条数与字数（不含夹注，夹注另作描述性计数） | 有限总体 |
| **E6** | 过度归因实验的效应 | 条目 × 随机重复 |

每个数字旁边都自动打印适用范围，例如："相对德格 D417–418（经宣奴贝修订），不是相对梵文"；"汉文列为以明本为底本的大正藏 T0892，含传抄中的变化"。

### 8.2 两阶段估计（`stats/twophase.py`，一个机制服务所有估计量）

- **第二阶段样本**：
  - 机器阳性中的罕见要类（无对应、反转、替换、类名略去、越窗、仅见于汉文、X 级）**全部**人工核验；
  - 常见类（部分、概括、散文音写）按"关系 × 主题组"分层抽样，总量上限 450，但每层至少 min(该层单元数, 20)；
  - 机器阴性按"等级 B/C × 主题组敏感/其他"分 4 层盲抽检，共 300，每层至少 40，C 级加倍。
- **分层冻结**：分层在**抽样那一刻冻结**，与计划一起保存为 `strata_<批次>.json`。以后导入的新标签不改变已冻结的分层。这是代码审查发现的一个关键问题：若重新计算分层，抽样设计就失效了。
- **插补**：每层以 Dirichlet(观测计数 + ½) 为后验，对未核验单元做后验预测插补，得到 500 套完整状态向量；每个估计量在每套上计算，取 2.5–97.5 百分位作为区间。
- **无法估计的分层**：有未核验单元、却没有任何样本裁决的分层，其估计只能来自先验，所以相关估计量打印 `NOT_ESTIMABLE`，G3 不通过。
- **未解决单元**：给出 Manski 界，即"全算偏移"与"全不算偏移"两种极端。
- **自动化偏差**：同一套代码改用"盲判"列，即得到"自动化偏差"的敏感性估计，与改判率一起报告。
- **差异误差的校正**：由于主题组是分层变量，敏感段落用敏感段落自己的误差率插补。"模型在敏感段落上更容易看见缺失"这类差异误差因此在构造上就被校正了。

### 8.3 Δ（E4，`stats/contrast.py`、`pipeline/e4.py`）

- **定义**：分层风险差 Δ = Σ w_c (r̄_敏感 − r̄_中性) / Σ w_c，分层 c = 品 × 参照长度的中位秩三分位。用中位秩是因为真实文本 3,042 个单元中有 2,503 个是 7 音节，按数值切点会让中间一档为空。
- **检验**：层内置换主题标签 2,000 次得 p 值；零结果用 TOST 报告为"在 ±MDE 内等价"，不写成"没有效应"。
- **诊断**：
  - 匹配风险差稳健性检查；
  - 按"品 × 长度三分位"的误判表；
  - 机器标签的朴素 Δ 与校正后 Δ 的衰减比较；
  - 叙述框架句上的负对照（应约为 0）。
- **功效**：主题标签齐全后，在真实标签上模拟最小可检测效应，写入 `stats/power.json`；G4 取它与预注册 MDE（0.10）中的较大者。
- **排除**：叙述框架句、真言对照、整表一致变化的单元、脱文。

### 8.4 分解（E3，`stats/decompose.py`、`pipeline/e3.py`）

对每个偏移单元，按顺序取第一个匹配的类。分类穷尽，代码断言各类总和等于偏移单元数：

1. `attested_vorlage`：夹注陈述底本缺此内容（"梵本元闕"）。另有 `attested_translator` 记录译者的替换说明；它只作标记，**不减少残余**。
2. `vorlage_ms`：至少一个有信息的梵文**写本**缺此内容或有异读。校勘本不算独立见证，录入了也搁置为 `editions_ignored`。
3. `shared`：共同见证也有同样的偏移。共同见证是经修订的德格本时标为 `shared_revised`。
4. `residual`：残余，即可能出自译者的部分。
5. `insufficient`：有信息写本不足 2 个，或共同见证不可计。

零模型：共享类报告观测数 O、独立假设下的期望 E 与 O − E，另报 φ_V、φ_S 两个超额比例。未经两列人工核验的"共享"按"非共享"处理，得到共享类的下界（A2 界）。

以德格本为参照时，"参照就是共同见证"，E3 如实打印 `NOT_ESTIMABLE`。只有接入梵文后才能真正计算。

### 8.5 其他

- `stats/distance.py`：梵文参照模式下，计算梵文参照、德格本、汉文三者之间的描述性距离与 UPGMA 树。
- `stats/power.py`：功效模拟。

## 9 人工复核流程

所有人工工作都在电子表格（UTF-8 带 BOM 的 CSV）里完成，不需要专门软件。逐列说明见 [`03-review-guide.md`](03-review-guide.md)。

**三条规矩**：

1. **先盲判，再看机器。** 盲表里没有任何机器结论。盲判导入后，才导出带机器结论的"揭示表"。两次判断都保存，改判率就是"自动化偏差"的指标。揭示时还会记录机器的极性判断 `machine_polarity_flip`。
2. **只按文本判断，不判断动机。**
3. **原文不入库。** 导出的表格带原文，只放在 `runs/` 下；导入时自动剥去原文列，引文截短到汉文 ≤ 30 字、藏文 ≤ 60 字，再写入 `data/annotations/`。有测试扫描该目录，防止长段原文入库。

**任务类型**：

| 任务 | 内容 |
|---|---|
| `gold` | 开发集或测试窗的金标准盲标（`--set dev / test / test_second`） |
| `verify` | 核验机器阳性 |
| `audit` | 抽检机器阴性 |
| `resolve` | 解决被拒、未对齐、模型被替换的单元；盲判即终裁，表中多一列 `hint_other_model` |
| `topics` / `topics_second` | 主题标注；第二编码者的表格不含 Claude 预标 |
| `reveal` | 揭示表 |

**典型循环**：

```bash
hevajra-matrix sample verification        # 抽核验计划（只抽一次，冻结分层）
hevajra-matrix sample audit               # 抽阴性抽检计划
hevajra-matrix review export --task verify --hours 4 --competence bo,zh
#   → 填盲表
hevajra-matrix review import --task verify --file <盲表> --annotator 姓名 --minutes 用时
hevajra-matrix review export --task reveal --batch <批次>
#   → 看机器结论后填终裁，如改判写原因
hevajra-matrix review reveal --file <揭示表> --annotator 姓名
hevajra-matrix review status              # 各层完成度
```

**队列**：`--hours H` 按优先级出 H 小时的题，已盲判的条目自动跳过。`--competence` 按所需语言能力（藏、汉、梵）筛选，不同专长的人可以各清各的题。

**防丢失**：表中还有未导入的条目时，导出会拒绝覆盖并列出这些条目；确认放弃后才能用 `--force`。

**计划与分层的保存**：计划 `plan_<批次>.csv` 与冻结的分层 `strata_<批次>.json` 写在 `data/annotations/verdicts/<见证>/` 下，只含 id，没有原文，与裁决一起提交。新的运行目录也会读取它们。

**工时**（约 90 小时，可分人、分语言进行）：

| 顺序 | 工作 | 工时 | 所需语言 |
|---|---|---|---|
| 1 | 开发集盲标 | 约 18 | 藏、汉 |
| 2 | 测试窗盲标 | 约 15 | 藏、汉 |
| 3 | 第二标注者（4 窗） | 约 5 | 藏、汉 |
| 4 | 哨兵签署 | 约 1 | 藏、汉 |
| 5 | 主题确认（＋第二编码者） | 约 8＋2 | 藏 |
| 6 | 解决被拒或未对齐的单元 | 视情况 | 藏、汉 |
| 7 | 罕见类核验 | 约 8 | 藏、汉（底本问题需梵） |
| 8 | 阴性抽检 | 约 10 | 藏、汉 |
| 9 | 常见类抽样核验 | ≤ 11 | 藏、汉 |
| 10 | 实验人工编码 | 约 5 | 英 |

**做完前三项（约 38 小时）即可达到"已验证"级**，这时已可单独写成方法或资源论文。

## 10 主题标注与组件层

### 10.1 主题（`topics/`）

- **词表**（`data/codebook/topics.yaml`）：
  - 八个敏感类，对应德重 2026 的八类：`sexual`、`female_agent`、`flesh_food`、`harm`、`theft`、`impure_substance`、`bone_corpse`、`ritual`；
  - `neutral`（必须单独出现）；
  - `frame`（叙述框架句，用作负对照）；
  - `mantra_control`（真言，作音写的负对照）。
- **流程**：Claude T3 **只读藏文**做预标（`topics prelabel`），第一编码者在此基础上确认；第二编码者标 20% 的单元，看不到预标。主题一致性 κ 只在两位人类之间计算。
- **为什么要隔离汉文**：标注主题时不能看汉文，否则会污染"敏感/中性"这个暴露变量。
- **顺序**：先做主题标注，再抽样。主题组是核验和抽检的分层变量；标签不完整时，`sample` 会打印警告。

### 10.2 组件层（`collate/components*.py`）

Claude T2 对已对齐的单元对逐槽位编码，得到描述性的"译法剖面"，例如哪些槽位常被概括、哪些被替换。在 150 对双人编码上报告逐码 P/R 之前，它不进入任何估计量。

## 11 过度归因实验

**问题**：当给出的证据表明某处汉文缺文可由底本或共享传统解释时，Claude 是否仍会断言译者动机？在敏感内容上，这种倾向是否更强？

这是一条可以独立发表的早期研究线，不必等全经核验完成。

**设计**：

- **内容**：敏感或中性，在条目之间变化。
- **证据**：在条目之内变化，共三种：
  - E0：无证据；
  - EP：等长的安慰剂句，例如"此段在所用刊本中位于汉译第三卷"；
  - EW：见证事实，分两种说法各半。EW-V 是"两个梵文写本同样缺此段"，EW-S 是"另一部独立译本同样缺此段"。
- 每个条件重复 3 次，条件顺序随机。**fallback 关闭**。结论只对 `claude-opus-5-5` 在实验日期成立。

**条目**：

- 60 条敏感、60 条中性，外加 10＋10 条预实验。
- 中性与敏感条目按同品或邻品、长度 ±25% 配对。
- `omission_origin` 记录缺文是"真实缺文（人工核实）"还是"构造缺文"。
- 条目库只入库坐标，文本在运行时从原文重建。

**受试（T4）**：effort 用 medium，即一般研究者实际得到的行为。

**评分**：

- **T5 盲评分器**：只看解释文本，对每个原因给出"断言 / 假设 / 否定 / 未提及"。这修正了审查指出的问题："否认动机"也曾被算作断言。
- **透明基线**：一套否定感知的词表规则，测试覆盖了 "This is not censorship"、"並非刪略" 这类句子。
- **人工锚定**：两位编码者盲编 150 条，编码表用不透明 id，不泄露实验条件。评分器对人工共识 κ ≥ 0.80 才作为主结果，否则用两阶段校正；无法校正的分层记为不可估计。

**假设**：

- H1：敏感组中有证据时，动机断言率下降。
- H2：无证据时，敏感 > 中性。
- H3：两者的交互。功效约 0.56，定为探索性。

**分析**：条目为分析单位，用配对条目自助法与符号翻转置换，Holm 校正多重比较。拒绝单列为一种结果，并按对比给出 Manski 界。

**目录**：预实验与正式实验的输出分开存放（`pilot/` 子目录）。

**操作**：

```bash
hevajra-matrix experiment overattribution plan
hevajra-matrix experiment overattribution run --phase pilot   # 预实验
hevajra-matrix experiment overattribution run --phase main
hevajra-matrix experiment overattribution score
```

规模约 1,080 次受试调用、约 1,300 次评分调用，同步价约 $90。详见 [`05-overattribution-experiment.md`](05-overattribution-experiment.md)。

**语言规范**由 `tests/unit/test_language_policy.py` 强制：

- `.py` 文件中不得出现非拉丁字符。原文字符一律写成转义或放在 `data/` 中。
- `docs-zh/` 以外的 md 文件不得出现非拉丁字符。

- 文件名一律 ASCII。
- 对已提交的数据目录做许可扫描，防止长段原文入库。

## 17 代码架构

| 包 | 职责 |
|---|---|
| `core/` | 类型（`Status`、`Relation`、`Grade`、`Segment`、`Link`、`Alignment`、`Cell`、`Verdict`、`Estimate`、`InstrumentId` 等，冻结的数据类）、坐标 id、文本归一化与指纹、词表、I/O、音写判定 |
| `ingest/` | CBETA、德格、梵文读取器，夹注分类 |
| `registry.py` | 见证清单与概表 |
| `align/` | 动态规划、相似度、锚点、洗牌对照、外部导入 |
| `llm/` | `LLMClient` 协议、schema、SDK 适配、假客户端、响应缓存、审计与预算、`claude-check` |
| `collate/` | 窗口规划、对勘请求、V1–V11 核验、块合并、共识、扰动、组件层 |
| `topics/` | 码本、标签、预标 |
| `matrix/` | 关系 → 状态、单元格构建、导出 |
| `review/` | 各类复核表格、裁决导入、抽样与队列 |
| `evaluation/` | 金标准评分、测试窗、窗口自助法、门控、哨兵 |
| `stats/` | 两阶段估计、Δ、分解、功效、距离 |
| `experiments/overattribution/` | 设计、运行、评分、词表基线、分析、人工编码 |
| `report/` | Markdown、各节、SVG |
| `pipeline/` | 各阶段的编排：运行上下文、文件存储、文本加载、工具指纹、度量、结果、E3、E4、复核、人工数据、实验 |
| `prereg.py`、`cli.py`、`config.py` | 预注册、命令行、配置加载 |

设计要点：

- 统计、核验、状态推导都是纯函数，易测。
- `pipeline/` 是唯一读写运行目录的地方。
- 所有 Claude 调用都经过同一条链：缓存 → 审计/预算 → SDK。测试时把 SDK 换成假客户端即可，不需要网络。

**在真实 T0892 与德格本上已验证**：

- 新基线已经修正审查指出的锚点错配：ཤ 不再命中 ཤེས，"嚩日囉"不再命中"日"。

**模拟的完整研究周期**：用假客户端模拟 Claude，用合成的人工裁决模拟专家，在真实文本上走完全程，验证了四件事：

- 报告级别按预期从 0 → 1 → 2 逐级上升；
- E1 恢复了植入的真值（估计 0.269，真值 0.265）；
- 一次被替换模型的调用使 G2 正确失败；
- 盲判 → 揭示 → 重新构建的往返中，裁决不会丢失。

这次模拟发现并修复了一批只有在完整周期中才暴露的问题，例如删句召回误计了其他窗口、重新导入盲判时覆盖了终裁、账本重复记录。

**代码审查**：多视角对抗式审查确认 64 项问题，全部修复。之后的回归审查又修复了约 10 项。

## 22 局限与暂缓项

- **没有做过任何真实的 Claude 调用**：容器中没有密钥。Claude 相关代码全部用假客户端测试，接口按官方 SDK 编写。首次实跑时，请先用 `claude-check` 与 `--dry-run` 确认。
- **结论只对特定模型版本成立**：由于不能设温度，结果绑定在工具指纹与响应缓存上。换模型或改提示词就是新工具，须重新过门控。
- **汉文列是单一的明本系见证**：其中混有传抄中的变化，报告的适用范围会写明这一点。
- **以德格本为临时参照**：德格本经过宣奴贝修订，"共享"类会被污染；E3 在接入梵文写本之前打印 `NOT_ESTIMABLE`。
- **暂缓实现**：
  - Batches 预热缓存：可省约一半费用，但会多一条代码路径；
  - 分解的品内循环平移零模型与各写本优势比：需要真实写本数据才有意义；
  - 组件层的验证：需要 150 对双人编码。
- **《老子》迁移模块已移除**，在 `main` 中完整保留。旧文档中的两处错误（乙本年代、章序）已记录在 `02-plan.md` §6，移植回来时一并改正。
- **再次强调**：自动化省的是检索和记账；判断仍须由懂藏、汉、梵文的人来做。
