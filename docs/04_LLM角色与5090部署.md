# 开源大模型在见证矩阵研究中的角色与单卡 5090 部署

版本 v0.1 · 与 `hevajra_matrix/llm/`、`data/llm/models.yaml` 同步

---

## 0 一句话定位

大模型在本项目中是**高通量的候选生成器与第二读者**，不是裁判：它把人手不够做的穷举式工作（对齐复核、命题切分、组件预填、主题预标、逐格说明）做到全覆盖，把人的工时集中到边界判断与历史解释；同时它本身是研究对象——过度归因动机的倾向、对已出版译本的记忆污染，都要被测量并报告。所有模型输出写入派生层，进入矩阵前必须通过与人工标注相同的机械检查（子串约束、固定标签集、证据门）。

这与《评估》和 docs/01 §3 第 4 条"加做 LLM 过度归因反事实实验"一致，并把该实验从一个附加项扩展为贯穿流水线的九个角色。

## 1 九个角色（R1–R9）与代码入口

| # | 角色 | 输入 → 输出 | 机械约束（代码强制，非 prompt 约定）| 入口 |
|---|---|---|---|---|
| **R1** | 跨语嵌入检索（B1 对齐基线）| 参照/见证片段 → 向量 → 余弦 | 只提供相似度，DP 与 NULL 先验不变；`hybrid` 模式下锚点优先 | `llm/embeddings.py`；`run --similarity embedding\|hybrid` |
| **R2** | 对齐复核 / 修复建议 | 可疑珠（1:0、0:1、1:3、3:1、2:2）＋前后文 → `accept / shift_left / shift_right / split / merge / make_null / unsure` | 裁决词表封闭；置信度 < 阈值降为 `unsure`；只写 `alignment_review.csv` 的 `review_status=llm:*`，**不改单元格证据等级** | `tasks.judge_bead / judge_review_rows`；`llm-judge` |
| **R3** | 命题切分 | 散文段 → 最小命题子串列表 | 必须按原序、无重叠、连续、覆盖 ≥ 90%，否则回退为不切 | `tasks.segment_propositions` |
| **R4** | 组件抽取（L3 预填）| 片段＋词典锚点 → 八槽位（行为者/动作/受事/工具/否定/条件/数量/结果）| 每个值必须是原文**逐字子串**；不在原文者进 `rejected`；`lexicon_keys` 只能取词典已检出的键 | `tasks.extract_components / component_deviation`；`llm-extract` |
| **R5** | 参照侧主题预标 | 梵文单元 → 固定主题集之一＋原文线索 | 只见参照文本，不见任何译本；标签集封闭；线索须为子串 | `tasks.label_topic` |
| **R6** | 归因分布（带弃判）| 编号事实列表 → `LABELS` 上的分布＋引用的事实号 | 标签集 = `attribution.LABELS`（无动机词）；概率归一；自由文本含动机词（正则 `MOTIVE_PATTERNS`）→ 整条降为 `abstain` 并记 `motive_flag` | `tasks.judge_attribution`；`llm-attribute` |
| **R7** | 多模型反事实 | 同一组缺文案例 × {无/有第二见证事实} × 多模型 | 动机断言判定只用固定正则；每个模型一行 | `tasks.counterfactual_across_models`；`llm-counterfactual` |
| **R8** | 记忆/污染探针 | 前缀 → 续写 → 与真实续文的字符 4-gram 召回 | 阈值预注册；按来源（84000、Snellgrove、Willemen、CBETA T0892、德格本）分别报告 | `tasks.contamination_probe`；`llm-probe` |
| **R9** | 逐格说明（rationale）| 单元格数值＋两侧文本 → ≤3 句"可观察差异"描述 | 含动机词 → `motive_flag`，只能进附录，不进正文 | `tasks.explain_cell` |

每一次调用记录 `model_id`、prompt/system/response 的 SHA-256、温度、seed、耗时（`backends.CallLog`），随输出一起落盘为 `*.calls.json`，与人工标注的签署记录同等对待。

## 2 哪些事模型**不做**

1. 不判定动机。`LABELS` 与主题集里没有"审查/自主规制/委婉"，正则守门把漏网的动机词降级为弃判。
2. 不直接写矩阵。R2 的裁决进 review 表，R4 的组件进 `derived/components.jsonl`，R6 的分布进 `derived/attribution_llm.csv`；从派生层到矩阵的每一步都由人签署或由确定性规则完成。
3. 不做金标准。嵌入相似度只是 DP 的一项代价；组件预填只是双人盲标的初稿；对任何一格，人工标注优先级高于模型。
4. 不看不该看的。R5 主题标注只看梵文；R6 只看编号事实，不看原文全文（避免模型用背景知识替代证据）。

## 3 单卡 RTX 5090（32 GB）部署

### 3.1 推荐拓扑

```
┌──────────────── RTX 5090 32 GB ────────────────┐
│ vLLM serve Qwen/Qwen3-32B-AWQ  (~20 GB 权重)    │  ← 独占 GPU，OpenAI 兼容 API :8000
│   --max-model-len 8192 --enable-prefix-caching │
└────────────────────────────────────────────────┘
          ▲ HTTP /v1/chat/completions (json_schema / guided_json)
┌─────────┴──────────────────────────────────────┐
│ hevajra_matrix  (纯 Python，无 GPU 依赖)        │
│   llm-judge / llm-extract / llm-attribute / …  │
└────────────────────────────────────────────────┘
```

- 流水线与模型解耦：换模型只改 `--llm <profile>`，代码零改动；`OpenAICompatibleBackend` 同时发送 `response_format.json_schema`（OpenAI/llama.cpp）与 `guided_json`（vLLM），保证结构化输出。
- 嵌入（R1）与生成模型不能同时驻留 32 GB：先用 `run --similarity hybrid` 离线算好嵌入缓存（bge-m3 2.3 GB，可与 8B 生成模型共存；Qwen3-Embedding-8B 需单独跑），再起 32B 服务。

### 3.2 模型选型（`data/llm/models.yaml`）

| profile | 模型 | 量化 | 显存 | 用途 | 许可 |
|---|---|---|---|---|---|
| `qwen3-32b-awq` | Qwen/Qwen3-32B-AWQ | Int4 | ≈ 20 GB + KV | 主力：R2/R4/R6/R9 | Apache-2.0 |
| `gemma3-27b` | google/gemma-3-27b-it | 4-bit | ≈ 17 GB + KV | 异家族复核；R7 必含 | Gemma Terms |
| `qwen3-14b-awq` | Qwen/Qwen3-14B-AWQ | Int4 | ≈ 9 GB | 长上下文（16k）批量任务 | Apache-2.0 |
| `qwen3-8b` | Qwen/Qwen3-8B | bf16（进程内）| ≈ 16 GB | notebook 迭代、R4 批量 | Apache-2.0 |
| `mitra-qwen3.5` | Dharmamitra MITRA（Qwen 微调，梵藏汉佛典）| — | 待核 | R2 复核；R8 重点探针对象 | 待核 |
| 嵌入 | BAAI/bge-m3 · MITRA-E · Qwen3-Embedding-8B/0.6B | — | 2.3 / ≈2 / 16 / 1.5 GB | R1 | MIT / 待核 / Apache-2.0 |

选型原则：(a) 至少两个不同家族（Qwen、Gemma）互为复核，R7 反事实实验必须跨家族报告；(b) 领域微调模型（MITRA）优先做检索与对齐复核，但因其训练集很可能含 84000 英译与 Snellgrove，**必须先过 R8 探针**再决定是否用于 R6；(c) 一切 4-bit 模型在关键任务上与 bf16 小模型抽样对比（≥ 200 例），差异写入方法论文。

### 3.3 环境注意事项

- Blackwell（sm_120）需 CUDA 12.8+、PyTorch ≥ 2.7、vLLM ≥ 0.8.5；bitsandbytes ≥ 0.45。若进程内 4-bit 报 "no kernel image"，改走 vLLM + AWQ（推荐路径，也更快）。
- Qwen3 默认开启 thinking；结构化任务在 system prompt 中加 `/no_think`，或在 `models.yaml` 的 note 中记录所用设置。`tasks.parse_json` 会剥离 `<think>…</think>`。
- 全部调用 `temperature=0`、`seed=20260930`；同一 prompt 跑两遍不一致时记录为"不确定"（vLLM 在批处理下不保证严格确定，需报告重复率）。
- 吞吐参考（Qwen3-32B-AWQ，8k 上下文，vLLM 单卡 5090，社区经验值，待实测）：R4 组件抽取约 3–5 例/秒（批处理）；1,300 单元 × 3 见证 的全量抽取在一小时量级；R2 对全部 NULL/n:m 珠（数百）几分钟。

## 4 评估：模型输出如何对照金标准

| 角色 | 金标准 | 指标 | 门槛（预注册）|
|---|---|---|---|
| R1 嵌入 vs B0 锚点 | 试标对齐（≥ 4 品人工对齐）| 珠级 P/R/F1；NULL 召回 | 嵌入或混合后端须在 NULL 召回上不劣于 B0 方可作为默认 |
| R2 对齐复核 | 人工复核的 review 表 | 裁决准确率；`unsure` 覆盖率 | 选择性风险–覆盖曲线；在 80% 覆盖下准确率 ≥ 0.9 |
| R3 命题切分 | 人工切分的品 | 边界 F1 | ≥ 0.85 |
| R4 组件抽取 | 双人盲标的 L3 子集 | 槽位级 P/R；`rejected` 比率 | 作为预填可用的门槛：槽位 F1 ≥ 0.75；`rejected` > 10% 则该模型不用于该语言 |
| R5 主题预标 | 两位标注者盲标 | κ | κ ≥ 0.7 |
| R6 归因 | 规则归因 `attribution.attribute` ＋ 人工复核样本 | 一致率；弃判率；`motive_flag` 率 | `motive_flag` 率是论文报告项，不是门槛 |
| R7 反事实 | — | 动机断言率（无事实）− 动机断言率（有事实），按模型 | 报告项 |
| R8 探针 | 真实续文 | 4-gram 召回均值；记忆率（≥ 0.5 的比例）| 记忆率 > 0.2 的来源，该模型对该见证的一切判断标 `contaminated` |

## 5 记忆污染：为什么必须先测

T0892 全文在 CBETA 上公开二十余年，84000 英译、Snellgrove 与 Willemen 的英译都可能在预训练语料中。若模型能续写出这些文本，则它在 R2/R6 中的"判断"可能只是回忆：例如它"知道"84000 英译在某处有一句，便倾向判定汉译"缺"——这不是证据，是泄漏。R8 探针对每个模型、每个来源报告记忆率；`contaminated` 标记随输出一路传到 `manifest.json`。方法论文中这一节本身就是贡献：把"模型记住了什么"当作与"抄手看到了什么"同构的 Vorlage 问题来处理（docs/03 §1 原则 3 的推广）。

## 6 与工作包的对应

| WP | 新增的 LLM 子任务 | 交付 |
|---|---|---|
| WP3 对齐 | R1 后端对比；R2 对全部 NULL/n:m 珠出裁决 | `alignment_review_llm.csv` + 后端对比表 |
| WP4 组件 | R3 切分预案；R4 双模型预填 → 双人盲标 | `derived/components.jsonl`；预填采纳率 |
| WP6 统计 | R5 主题预标（盲于译本）→ 匹配对照的分层变量 | `derived/topics.csv`；κ |
| WP7 归因 | R6 ＋ R7 跨模型 ＋ R8 探针 | 弃判校准报告；反事实表；污染表 |
| WP8 写作 | R9 生成逐格说明附录（人工审阅后）| 附录 |

人力瓶颈（docs/01 §5）不因模型而消失：模型把 600–1,000 小时的组件标注变为"复核预填"，经验上可省 30–50% 工时，但双人盲标的设计不变，否则 α 无法计算。
